# 日报矢量长海报 PDF 输出设计

- 日期：2026-08-01
- 状态：用户已确认
- 基础版本：`codex/daily-report-generator`

## 1. 目标

程序直接读取 `daily/YYYY-MM/` 下的普通 Markdown 日报，将其排版为固定 1080 px 逻辑宽度、内容驱动高度的单页长海报，并且只保留一个矢量 PDF 成品。

文字、CSS 色块、边框和 SVG 装饰由 Chromium 直接写入 PDF，避免整张海报先转成位图造成的放大模糊。日报中原本引用的位图仍按其源文件分辨率嵌入。

## 2. 输入与输出

输入文件必须位于：

```text
daily/YYYY-MM/
```

支持两种文件名：

```text
YYYY-MM-DD.md
YYYY-MM-DD-DD.md
```

第二种形式表示同一个月内连续多日的合并日报。输出目录固定为输入文件所在月份目录下的 `images/`：

| 输入 | 输出 |
|---|---|
| `daily/2026-08/2026-08-01.md` | `daily/2026-08/images/1.pdf` |
| `daily/2026-07/2026-07-09-11.md` | `daily/2026-07/images/9-11.pdf` |
| `daily/2026-07/2026-07-30-31.md` | `daily/2026-07/images/30-31.pdf` |

日期中的前导零不进入 PDF 文件名。程序不生成 PNG、JSON、manifest 或日期子目录。

## 3. Markdown 兼容范围

输入以现有 `daily/` 日报为准，不要求 YAML Front Matter、项目代码、状态字段或固定栏目。首版支持现有文件需要的常用 Markdown：

- 一级至三级标题
- 普通段落
- 有序和无序列表
- 引用块
- 粗体、斜体、行内代码和链接
- 围栏代码块
- 独占一行的本地 Markdown 图片

不支持的结构必须保留可读文本或给出明确错误，不得静默丢失正文。原始 Markdown 文件只读，生成过程不得改写日报内容。

为避免增加新的项目依赖，解析层沿用现有逐行解析方式，输出由标题、段落、列表、引用和代码块组成的受控文档模型，再由 React 组件渲染。Markdown 中的原始 HTML 不执行，而是作为普通文本显示；链接只生成可点击的安全 URL，不注入任意标签或脚本。

## 4. 渲染与 PDF

渲染页面使用现有 React、CSS 和 Playwright Chromium 链路，但数据入口改为普通 Markdown 文档模型。海报规则如下：

- 根节点逻辑宽度固定为 1080 px。
- 高度由完整内容自动计算，最低高度沿用现有模板要求。
- 不分页、不缩小字号、不裁切正文。
- 浏览器等待字体和资源加载完成后再测量最终高度。
- `page.pdf()` 使用测得的宽高、零页边距和背景打印。
- PDF 保留浏览器可表达的矢量文字与图形；位图素材不做无意义的整页放大。

若内容高度超过 Chromium 可可靠导出的上限，程序应停止并报告原因，不生成截断 PDF。

## 5. 写入与覆盖

生成时先在项目缓存目录写入临时 PDF，确认文件存在、非空且为单页后，再替换目标 PDF。若解析、资源加载、布局检查或 PDF 验证失败：

- 保留已有目标 PDF；
- 清理本次临时文件；
- CLI 返回非零退出码和可操作的错误信息。

同名 PDF 默认重新生成并安全覆盖，因此修改日报后重复执行同一条命令即可更新成品。

## 6. 命令行体验

主要用法保持为一条命令：

```powershell
npm.cmd run report -- "daily\2026-07\2026-07-30-31.md"
```

成功信息只报告 PDF 路径。`--open`、`--dry-run` 和 `--verbose` 可继续保留；仅服务于 PNG 的 `--scale` 不再参与渲染。

## 7. 验证

自动测试至少覆盖：

- 单日文件名映射为不带前导零的数字 PDF；
- 多日文件名映射为 `起始日-结束日.pdf`；
- 输出目录始终是对应月份的 `images/`；
- 不创建 PNG、JSON、manifest 和额外日期目录；
- 现有普通 Markdown 的标题、段落、列表和代码块不会丢失；
- PDF 为单页、尺寸与测得海报尺寸一致且文件非空；
- 生成失败时旧 PDF 保持不变；
- CLI 帮助和 README 示例与实际行为一致。

最终验证运行单元测试、端到端测试、TypeScript/Vite 构建，并使用一份 `daily/` 真实格式夹具生成 PDF，检查页数、输出路径和不存在多余成品。

## 8. 非目标

本次不实现 PNG 输出、多页 A4、Figma 自动同步、Git 自动提交、跨月合并日报、多模板切换或 Web 编辑器。
